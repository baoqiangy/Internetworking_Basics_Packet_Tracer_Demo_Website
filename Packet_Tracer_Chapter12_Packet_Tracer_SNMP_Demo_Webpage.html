Cisco Packet Tracer Lab: SNMP Network Monitoring

Cisco Packet Tracer 9.x  ·  Estimated time: 30–45 minutes  ·  SNMPv2c

In this lab, you will configure Cisco devices as SNMP agents, retrieve management information from a monitoring PC, and examine SNMP messages in Packet Tracer Simulation Mode.

1. Learning objectives

  1. Distinguish an SNMP manager from an SNMP agent.
  2. Configure SNMPv2c read-only monitoring on a router and a switch.
  3. Query MIB objects using an SNMP MIB Browser.
  4. Identify common SNMP Object Identifiers (OIDs).
  5. Observe SNMP GET and RESPONSE packets in Simulation Mode.
  6. Explain how event-driven SNMP traps differ from polling.

2. Network topology and addressing

Required equipment

  • 1 Cisco 2911 router (R1)
  • 1 Cisco 2960 switch (S1)
  • 2 PCs (PC0 and PC1)
  • 3 copper straight-through cables

Build the topology

  1. Add and rename the devices as shown.
  2. Connect R1 G0/0 to S1 Fa0/1.
  3. Connect PC0 FastEthernet0 to S1 Fa0/2.
  4. Connect PC1 FastEthernet0 to S1 Fa0/3.

3. Configure the router (R1)

Open R1 → CLI and enter:

enable
configure terminal
hostname R1

interface gigabitEthernet0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
exit

snmp-server community MONITOR123 RO
snmp-server location Network-Lab
snmp-server contact netadmin@example.com

end
write memory
Explanation: snmp-server community MONITOR123 RO establishes a read-only SNMPv2c community string. The MIB Browser must supply the same community string to read the router’s SNMP data.

4. Configure the switch (S1)

Open S1 → CLI and enter:

enable
configure terminal
hostname S1

interface vlan 1
 ip address 192.168.10.2 255.255.255.0
 no shutdown
exit

ip default-gateway 192.168.10.1

snmp-server community MONITOR123 RO
snmp-server location Network-Lab
snmp-server contact netadmin@example.com

end
write memory

The VLAN 1 interface requires an active port in VLAN 1 to become operational. The connected switch ports use VLAN 1 by default.

5. Configure the PCs and verify connectivity

  1. On each PC, navigate to Desktop → IP Configuration.
  2. Enter the IP address, subnet mask, and default gateway from the table.
  3. On PC0, open Desktop → Command Prompt.
  4. Run these commands:
ping 192.168.10.1
ping 192.168.10.2
ping 192.168.10.101

Expected result: Each destination replies to ping. If the first attempt fails, allow time for interfaces and ARP resolution, then try again.

6. Demonstrate SNMP polling with the MIB Browser

  1. On PC0, open Desktop → MIB Browser.
  2. Set the target address to 192.168.10.1.
  3. Choose SNMP v2c, UDP port 161, and read community MONITOR123. Depending on the Packet Tracer version, these may be under Advanced settings.
  4. Navigate the MIB tree to iso → org → dod → internet → mgmt → mib-2 → system.
  5. Find sysName and issue a GET request for instance 0 (full OID 1.3.6.1.2.1.1.5.0).
  6. Observe the returned value. It should identify the router as R1.
  7. Try the additional OIDs below.
  8. Change the target to 192.168.10.2 and repeat the queries for the switch.
OIDObjectWhat it returns
1.3.6.1.2.1.1.1.0sysDescrDevice/system description
1.3.6.1.2.1.1.3.0sysUpTimeTime since the SNMP management subsystem initialized
1.3.6.1.2.1.1.5.0sysNameDevice name
1.3.6.1.2.1.1.4.0sysContactAdministrator contact
1.3.6.1.2.1.1.6.0sysLocationConfigured location
Expected observations: sysName.0 = R1 on the router, sysName.0 = S1 on the switch, and configured contact/location values if those objects are implemented by the simulated device. The exact MIB tree and controls vary by Packet Tracer release.

7. Examine SNMP traffic in Simulation Mode

  1. Select Simulation at the bottom of Packet Tracer.
  2. Open Edit Filters and enable SNMP (and ARP if necessary).
  3. Return to PC0’s MIB Browser and issue another GET request for sysName.0.
  4. Click Capture/Forward to step through the packet flow.
  5. Click the packet envelope to examine protocol details.

Record the SNMP PDU type, requested OID, UDP destination port, and returned value. Observe the community string if Packet Tracer exposes it in the packet details.

8. Optional extension: SNMP traps

Unlike GET requests, SNMP traps are unsolicited notifications initiated by a device, typically toward an SNMP manager on UDP port 162.

On routers that support the commands, trap configuration may resemble:

enable
configure terminal
snmp-server host 192.168.10.100 version 2c MONITOR123
snmp-server enable traps snmp linkdown linkup
end
Packet Tracer limitation: Trap command support and trap reception are not consistently implemented across simulated Cisco devices and Packet Tracer releases. The standard Packet Tracer PC MIB Browser should not be assumed to function as a trap receiver. This extension is conceptual unless you have verified the specific device and receiver support in your version.

Important design consideration: Do not shut down R1’s only management interface G0/0 to test delivery: doing so disconnects the router from the receiver. On a system with working trap support, trigger an event on a separate monitored interface while leaving the management connection up.

For a full hands-on trap demonstration, use real Cisco IOS or a network emulator with an SNMP-capable receiver such as a trap listener on a Linux VM.

9. Troubleshooting

SymptomWhat to check
Ping failsAddresses, physical links, switch port status, router no shutdown.
GET request times outDestination IP, read community, SNMP version, and UDP port 161.
Unexpected device nameVerify the target IP address; inspect hostname configuration.
SNMP packets not visibleConfirm Simulation Mode and SNMP event filters; trigger a new query.
Trap command rejectedThe simulated platform may not implement the command.
Switch management inaccessibleVerify VLAN 1 interface and at least one active VLAN 1 port.

10. Review questions

  1. What role does an SNMP agent perform?
  2. How do SNMP GET and RESPONSE messages differ?
  3. Which UDP destination port is normally used for SNMP polling?
  4. What information does OID 1.3.6.1.2.1.1.5.0 identify?
  5. What happens when the MIB Browser uses an incorrect community string?
  6. How does an SNMP trap differ from periodic polling?
  7. Why is SNMPv3 generally preferred over SNMPv2c in production networks?

11. Completion checklist

Expected result: You can remotely read available management values from R1 and S1 and trace an SNMP GET/RESPONSE exchange. You can explain how a trap would instead be generated by a device in response to an event.

Security note: This lab uses SNMPv2c for instructional simplicity. Its community strings are not encrypted. Production monitoring should use SNMPv3 with authentication and privacy where supported.
