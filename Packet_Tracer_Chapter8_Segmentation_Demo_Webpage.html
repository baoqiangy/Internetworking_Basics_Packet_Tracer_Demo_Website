1. Lab Purpose

Demonstrate how one physical switching infrastructure can carry separate logical networks. Students create staff, student, and server VLANs, carry them across trunks, and use router subinterfaces to enable communication between them. An optional access-control demonstration then distinguishes traffic separation from security policy.

  • Divide a /24 address block into /26 subnets.
  • Assign switch access ports to VLANs and connect switches with an 802.1Q trunk.
  • Observe same-VLAN communication across switches before routing is enabled.
  • Configure router-on-a-stick and test shared DNS and HTTP services.
  • Restrict student-to-staff traffic while preserving access to the server.
  • Diagnose VLAN membership, trunk, gateway, and subnet-mask errors.
Instructor note: This is an original live demo with guided practice, not a graded assignment. No submission requirements are included. The main lesson is segmentation; the ACL is a short policy extension.

2. Lab Scenario

Northstar Training Center shares two access switches between staff and students. The administrator wants separate broadcast domains for staff, students, and services without buying a switch for every group. Both groups need access to a shared web and DNS server.

Learning Objectives

  • Explain the relationship between a VLAN and its IP subnet in this design.
  • Calculate /26 network addresses, host ranges, and broadcast addresses.
  • Distinguish access ports from tagged trunks.
  • Configure and verify VLANs on both switches.
  • Explain why traffic between VLANs needs a Layer 3 device.
  • Test the difference between routing availability and an explicit traffic policy.

Part G — Configure Router-on-a-Stick

On RTR-HQ-01, answer no to the initial configuration dialog if prompted. The physical interface has no IP address; each subinterface supplies one subnet's gateway.

enable
configure terminal
hostname RTR-HQ-01
interface gigabitEthernet0/0
 description 802.1Q trunk to SW-HQ-01
 no ip address
 no shutdown
 exit
interface gigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 192.168.80.1 255.255.255.192
 exit
interface gigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 192.168.80.65 255.255.255.192
 exit
interface gigabitEthernet0/0.30
 encapsulation dot1Q 30
 ip address 192.168.80.129 255.255.255.192
 exit
end
copy running-config startup-config

The subinterface number is a naming convention; the encapsulation dot1Q command actually selects the VLAN ID.

6. Verify Segmentation and Routing

Part H — Inspect the Switches and Router

On both switches:

show vlan brief
show interfaces trunk

Confirm VLANs 10, 20, and 30 exist, access ports have the intended memberships, and active trunks allow all three VLANs. Trunks are checked with show interfaces trunk; they are not listed as ordinary VLAN access members in show vlan brief.

On the router:

show ip interface brief
show ip route

Expect G0/0 and all three subinterfaces up/up, and connected routes for 192.168.80.0/26, 192.168.80.64/26, and 192.168.80.128/26. An up/up subinterface alone does not prove its VLAN is allowed on the switch trunk.

Part I — Test from Clients

From PC-STAFF-01:

ipconfig
ping 192.168.80.1
ping 192.168.80.11
ping 192.168.80.70
ping 192.168.80.130
ping portal.northstar.com

All should succeed before the ACL is installed. On both student PCs, test their gateway 192.168.80.65, the server 192.168.80.130, and the portal name. On all four clients, use Desktop > Web Browser to open http://portal.northstar.com. Also try http://192.168.80.130 to separate DNS from HTTP troubleshooting.

Checkpoint: Save a verified copy as Chapter8_Segmentation_Baseline.pkt. Use a separate working copy for policy and fault demonstrations.

Part J — Simulation Mode: Broadcast Boundaries

  1. Select Simulation Mode and filter ARP and ICMP.
  2. From PC-STAFF-01 ping PC-STAFF-02. Step through events with Capture/Forward.
  3. Observe that staff ARP broadcasts stay inside VLAN 10, including across the switch trunk; student and server access ports do not receive them.
  4. Next ping the server. The PC resolves its gateway MAC, not the remote server MAC. The router performs a separate ARP lookup in VLAN 30 when needed.
  5. Inspect PDU details on trunk and access links to discuss VLAN tagging, where the simulator exposes it.
  6. Add DNS, TCP, and HTTP filters and request the portal. Return to Realtime afterward.

Previously learned ARP/DNS entries can hide lookup events. Restart a client in a saved working copy if a fresh lookup is needed; clearing the event list alone does not necessarily clear caches.

7. Segmentation Policy Demo

Part K — Add a Student-to-Staff Restriction

VLANs separate Layer 2 broadcasts. After routing is enabled, all three subnets can communicate unless a policy says otherwise. This extension drops IP traffic entering from the student subnet with a staff-subnet destination, while allowing its other IP traffic.

On RTR-HQ-01:

enable
configure terminal
ip access-list extended STUDENT-IN
 deny ip 192.168.80.64 0.0.0.63 192.168.80.0 0.0.0.63
 permit ip any any
 exit
interface gigabitEthernet0/0.20
 ip access-group STUDENT-IN in
 exit
end
show access-lists
show ip interface gigabitEthernet0/0.20

The /26 wildcard 0.0.0.63 matches the last six address bits. ACL entries are evaluated in order. The final permit preserves other traffic for this focused demo; without it the implicit deny would block unmatched traffic, including student access to services.

Part L — Verify the Policy

TestExpected Result
Student .70 → staff .10 pingBlocked by the inbound student ACL
Student .70 → student .71 pingSuccess within VLAN 20; bypasses router ACL
Student .70 → server .130 ping and portal HTTPSuccess; destination is in VLAN 30
Staff .10 → server .130 ping and portal HTTPSuccess
Staff .10 → student .70 pingFails: student echo replies toward staff are also blocked
Stateless policy: This ACL does not distinguish new sessions from replies. Do not describe it as “staff can initiate unrestricted connections to students.” It also does not isolate students from one another within VLAN 20 or provide a complete firewall policy.

Inspect show access-lists for rule matches where supported. If preserving this variant, save it separately as Chapter8_Segmentation_Policy.pkt.

Part M — Restore the Baseline Policy

Remove the ACL attachment before the troubleshooting demonstrations:

configure terminal
interface gigabitEthernet0/0.20

no ip access-list extended STUDENT-IN
end

Retest student-to-staff and staff-to-student ping; both should work again.

8. Troubleshooting Demonstrations

One fault at a time: Start with the verified baseline and no ACL. Introduce one fault, predict its scope, test it, and restore it before continuing. Do not save a fault over the baseline.

Demo 1 — Wrong Access VLAN

On SW-HQ-02 move the staff PC's port into VLAN 20:

enable
configure terminal
interface fastEthernet0/1
 switchport access vlan 20
end

PC-STAFF-02 keeps its staff IP but loses ordinary staff and gateway connectivity. Check show vlan brief. Repair on SW-HQ-02:

configure terminal
interface fastEthernet0/1
 switchport access vlan 10
end

Demo 2 — VLAN Missing from the Trunk

On SW-HQ-01 exclude VLAN 20 from the inter-switch trunk:

configure terminal
interface gigabitEthernet0/2
 switchport trunk allowed vlan 10,30
end

PC-STUDENT-02 loses its gateway and server access, while PC-STUDENT-01 and staff clients still work. Inspect show interfaces trunk on both switches. Restore:

configure terminal
interface gigabitEthernet0/2
 switchport trunk allowed vlan 10,20,30
end

Demo 3 — Incorrect Subnet Mask

Change PC-STAFF-01's mask to 255.255.255.0. It now treats the server .130 as local and ARPs for it in VLAN 10 rather than using the gateway.

Make the observation deterministic: IOS proxy ARP can mask this error. Before the fault, on RTR-HQ-01 enter interface gigabitEthernet0/0.10 in configuration mode and apply no ip proxy-arp. With the /24 mask, a fresh server ping should fail and Simulation Mode should show the incorrect ARP target. If the installed model rejects this command, teach the wrong local/remote decision from ARP events rather than promising a failure.

Restore the PC mask to 255.255.255.192. If proxy ARP was disabled for this demonstration, restore it with ip proxy-arp on G0/0.10. Retest the server and portal.

Demo 4 — Wrong Default Gateway

Change PC-STUDENT-02's gateway to unused 192.168.80.126. Its same-VLAN peer remains reachable, but server access fails. Inspect ipconfig and restore 192.168.80.65.

Demo 5 — Router Physical Interface Down

On RTR-HQ-01 enter configuration mode, select G0/0, and apply shutdown. Same-VLAN communication across the switch trunk still works; inter-VLAN communication fails. Inspect show ip interface brief. Restore with no shutdown on G0/0 and wait for recovery.

Troubleshooting Decision Table

SymptomCheck First
One PC cannot reach its same-VLAN peerCable, address/mask, access VLAN, and trunk allowed list
One VLAN fails only across switchesVLAN existence on both switches and inter-switch trunk
Same-VLAN works; all inter-VLAN failsRouter link, switch-to-router trunk, and subinterfaces
One VLAN cannot reach its gatewayGateway address, dot1Q VLAN ID, and allowed VLANs
Server IP works; name failsClient DNS address and server A record
Traffic fails only after policy is appliedACL order, direction, subnet wildcard, and return traffic

End by confirming all four PCs reach the server by IP and name, staff peers communicate, student peers communicate, and cross-VLAN ping works with the ACL removed.

9. Instructor Explanation Blocks

VLAN vs. Subnet

A VLAN is a Layer 2 broadcast domain. A subnet defines a Layer 3 address range. This design maps one subnet to each VLAN. Changing a PC's IP address does not change the VLAN assigned to its switch port.

Access vs. Trunk

An access port places an ordinary endpoint's untagged traffic into one VLAN. A trunk carries multiple VLANs over one link. An allowed VLAN list limits which VLANs may traverse that trunk; it does not create the VLANs automatically.

Broadcast vs. Collision Domain

Switch ports separate Ethernet collision domains; full-duplex switched links do not use collision detection during normal operation. VLANs separate broadcast domains. A router does not simply forward a received Layer 2 broadcast into all its other VLANs.

Routing vs. Filtering

A trunk transports VLAN traffic; it does not route between VLANs. The router performs that routing, and an ACL can then filter selected packets. VLAN separation alone does not enforce a restrictive inter-VLAN policy after unrestricted routing is enabled.

Capacity and Design

Router-on-a-stick makes the shared gateway function easy to observe, but inter-VLAN traffic shares one physical router link and depends on one router. Larger networks often use multilayer switches and resilient designs. This demo does not measure throughput or implement redundancy.

Questions and Expected Answers

  • Why /26? Four equal blocks of 64 addresses fit inside the /24; each conventional LAN block has 62 usable addresses.
  • Is 192.168.80.127 a valid student host? No; it is the student subnet's broadcast address.
  • Can staff PCs on different switches communicate without the router? Yes, through VLAN 10 on the switch trunk.
  • Does the ACL affect student-to-student traffic? No; same-VLAN traffic does not pass through that router interface.
  • Does an up/up router subinterface prove end-to-end VLAN transport? No; switch VLAN membership and trunk configuration must also be checked.

11. Final Demo Summary

Trace a student request to the shared portal:

PC-STUDENT-02 opens http://portal.northstar.com 1. Its /26 mask identifies the DNS/server address as off-subnet. 2. It sends traffic to gateway 192.168.80.65. 3. SW-HQ-02 carries VLAN 20 across the inter-switch trunk. 4. SW-HQ-01 carries VLAN 20 to router subinterface G0/0.20. 5. The router evaluates any inbound ACL and routes toward VLAN 30. 6. G0/0.30 sends server-bound traffic tagged for VLAN 30. 7. DNS resolves the portal name; TCP/HTTP carries the page request. 8. Server responses return through gateway 192.168.80.129.
Key lesson: Subnets organize IP addresses, VLANs separate broadcast domains, trunks carry multiple VLANs, routers connect subnets, and filtering rules control which routed traffic is permitted.
