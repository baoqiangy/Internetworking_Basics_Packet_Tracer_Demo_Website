Demo 8.1 — VLANs, Trunks, and Router-on-a-Stick

Demo time50–60 minutes
Devices1 router, 2 switches, 6 PCs
Primary focusVLANs, 802.1Q, inter-VLAN routing

Before class

Use VLAN 10 Admin, VLAN 20 Faculty, and VLAN 30 Students. Assign one PC in each VLAN on each switch.

Live demonstration procedure

  1. Create VLANs on both switches and name them.
  2. Assign access ports to the correct VLANs. Use show vlan brief.
  3. Ping between two same-VLAN PCs located on different switches before configuring the inter-switch trunk; show failure.
  4. Configure the inter-switch link as an 802.1Q trunk. Repeat the same-VLAN ping and show success.
  5. Ping between different VLANs and show failure because switches do not route between broadcast domains.
  6. Configure the switch-to-router link as a trunk. On the router, create subinterfaces G0/0.10, .20, and .30 with encapsulation dot1Q and gateway addresses.
  7. Assign PC default gateways and test inter-VLAN communication.
  8. Use Simulation Mode to show an ARP broadcast staying inside one VLAN and routed traffic being re-encapsulated.
  9. Deliberately remove VLAN 20 from a trunk or assign a port to the wrong VLAN. Troubleshoot with show interfaces trunk and show interfaces switchport.

Command reference

vlan 10
 name ADMIN
vlan 20
 name FACULTY
vlan 30
 name STUDENTS
interface g0/1
 switchport mode trunk

interface g0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0

What students should observe

Same-VLAN traffic crosses a trunk without routing; different-VLAN traffic requires a Layer 3 gateway.

Teaching prompts

Ask: “Does a VLAN create a physical boundary or a logical broadcast boundary?”

Demo 8.2 — Turn a Written Policy into an ACL

Demo time45–50 minutes
DevicesTopology from Demo 8.1 plus server VLAN
Primary focusExtended ACL placement and rule order

Before class

Add VLAN 40 Servers with DNS/web server 192.168.40.10. Begin with unrestricted routing.

Live demonstration procedure

  1. State the policy aloud: Admin can reach everything; Faculty can reach web and DNS on the server; Students can reach DNS and web but not Admin; all other Student-to-internal traffic is denied.
  2. Translate each sentence into source, destination, protocol, and port fields before typing IOS commands.
  3. Create a named extended ACL STUDENT-IN. Permit UDP/53 and TCP/80 to the server, deny Student-to-Admin, then permit other required traffic.
  4. Apply the ACL inbound on the Student subinterface.
  5. Test each policy case from a Student PC and use show access-lists after every test.
  6. Deliberately put a broad deny above a permit. Show that first-match processing prevents the later permit from being reached.
  7. Correct the order and explain the implicit deny at the end.
  8. Use Simulation Mode to inspect a dropped packet at the router.

Command reference

ip access-list extended STUDENT-IN
 permit udp 192.168.30.0 0.0.0.255 host 192.168.40.10 eq 53
 permit tcp 192.168.30.0 0.0.0.255 host 192.168.40.10 eq 80
 deny ip 192.168.30.0 0.0.0.255 192.168.10.0 0.0.0.255
 permit ip 192.168.30.0 0.0.0.255 any
interface g0/0.30
 ip access-group STUDENT-IN in
show access-lists

What students should observe

ACL behavior follows top-down, first-match logic. Correct placement and order are as important as the individual statements.

Teaching prompts

Ask students to verbally predict the matching line before each test.
