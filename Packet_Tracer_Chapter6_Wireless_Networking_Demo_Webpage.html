1. Lab Purpose

The purpose of this demo lab is to help students understand how wireless networks are built, secured, documented, and tested. Students will see that wireless networking is not just “Wi-Fi.” A working wireless network requires correct physical placement, SSID configuration, security settings, addressing, DHCP, DNS, and troubleshooting.

This lab demonstrates:

  • Basic wireless infrastructure using a wireless router and wireless clients.
  • SSID naming and wireless association.
  • WPA2-Personal security configuration.
  • DHCP addressing for wireless clients.
  • DNS and HTTP testing over Wi-Fi.
  • Wireless troubleshooting for wrong password, wrong SSID, DHCP failure, and coverage issues.
  • The difference between wired infrastructure and wireless access.
Instructor note: This is a demo lab, not an assignment lab. It is designed for live teaching, step-by-step explanation, and classroom discussion. It does not include submission requirements, grading, or required screenshots.

2. Lab Scenario

You are expanding the network for Northstar Training Center. The wired LAN already has a router, switch, and server. The organization now wants to add wireless access for instructors, staff, and guests.

The network administrator wants to demonstrate:

  1. How a wireless access point or wireless router connects wireless devices to the LAN.
  2. How SSID and security settings affect client connectivity.
  3. How DHCP provides IP configuration to wireless devices.
  4. How DNS and web services can be accessed over Wi-Fi.
  5. How common wireless problems are diagnosed.

Learning Objectives

  • Explain the purpose of an SSID.
  • Configure a basic wireless network in Packet Tracer.
  • Configure WPA2-Personal security.
  • Connect laptops and smartphones to a wireless network.
  • Verify IP address assignment using DHCP.
  • Test connectivity using ping, browser access, and DNS names.
  • Explain how channel selection and physical placement affect wireless performance.
  • Troubleshoot common wireless connectivity problems.

6. Verify Wireless Connectivity

Part I — Check IP Configuration

On each wireless laptop, open Desktop > Command Prompt and run:

ipconfig

Expected values:

FieldExpected Result
IP address192.168.61.100 or higher
Subnet mask255.255.255.0
Default gateway192.168.61.1
DNS server192.168.60.10

Part J — Ping the Wireless Gateway

From LAP-HQ-STAFF-01, run:

ping 192.168.61.1

This confirms that the wireless client can reach the wireless router’s LAN interface.

Part K — Ping the Server

From LAP-HQ-STAFF-01, run:

ping 192.168.60.10

If this works, the wireless client can reach a service on the wired LAN.

Part L — Test DNS

From LAP-HQ-STAFF-01, run:

nslookup www.northstar.local

Expected result:

Name:    www.northstar.local
Address: 192.168.60.10

Part M — Test Web Access

On LAP-HQ-STAFF-01, open the web browser and test:

http://192.168.60.10

Then test:

http://www.northstar.local
Instructor explanation: If the IP address works but the domain name fails, wireless connectivity is working but DNS is probably misconfigured.

Part N — Simulation Mode

  1. Switch Packet Tracer to Simulation mode.
  2. Clear the event list.
  3. Filter for ARP, ICMP, DNS, TCP, and HTTP.
  4. From a wireless laptop, open http://www.northstar.local.
  5. Use Capture / Forward to step through traffic.

Discuss the sequence:

  1. The wireless client associates to the SSID.
  2. The client receives DHCP addressing.
  3. The client asks DNS to resolve the website name.
  4. The client sends web traffic to the server.
  5. The wireless router forwards traffic between the wireless side and wired side.

Part Q — Channel Planning Concept

In a 2.4 GHz Wi-Fi discussion, introduce the idea that channels overlap. Channels 1, 6, and 11 are commonly used because they are spaced apart to reduce overlap. Packet Tracer may not simulate all real-world interference behavior, but it is useful for explaining the concept.

2.4 GHz example: AP 1: Channel 1 AP 2: Channel 6 AP 3: Channel 11 Goal: Reduce co-channel and adjacent-channel interference.

Part R — Guest Network Concept

Explain that a real organization often separates staff and guest Wi-Fi. Guest devices should not automatically have the same access as internal staff devices.

8. Wireless Troubleshooting Demonstrations

Demo 1 — Wrong Wi-Fi Password

  1. On LAP-HQ-STAFF-02, attempt to connect to Northstar-Staff.
  2. Enter the wrong passphrase, such as wrongpassword.
  3. Observe that the client cannot connect.
  4. Enter the correct passphrase: N0rthstar-WiFi!.
  5. Confirm the client connects successfully.

Teaching point: A wrong Wi-Fi password prevents wireless association or authentication.

Demo 2 — Wrong SSID

  1. Change the wireless router SSID from Northstar-Staff to Northstar-Staff-New.
  2. Show that existing clients may lose connectivity or fail to reconnect.
  3. Update the client profile to the new SSID.
  4. Reconnect and test again.

Teaching point: The SSID on the client must match the wireless network name.

Demo 3 — DHCP Failure

  1. Temporarily disable DHCP on the wireless router.
  2. Set one wireless laptop to request DHCP.
  3. Observe that it cannot receive the expected 192.168.61.x address.
  4. Re-enable DHCP.
  5. Reconnect or renew the client.

Teaching point: Association to Wi-Fi is not enough. The client also needs valid IP settings.

Demo 4 — Wrong DNS Server

  1. On LAP-HQ-STAFF-01, manually set DNS to an unavailable address such as 8.8.8.8.
  2. Test http://192.168.60.10. It should still work.
  3. Test http://www.northstar.local. It should fail.
  4. Set DNS back to 192.168.60.10.
  5. Retest the domain name.

Teaching point: If IP works but names fail, troubleshoot DNS.

Demo 5 — Wireless Coverage Concept

Packet Tracer allows devices to be moved around the workspace. Move a wireless client farther away from the wireless router and discuss signal strength, distance, walls, interference, antenna placement, and AP density.

Instructor explanation: Packet Tracer is a simulator, so it may not perfectly represent real RF behavior. Use this portion mainly to introduce the idea that physical placement matters in wireless design.

9. Instructor Explanation Blocks

SSID

The SSID is the wireless network name. Clients use the SSID to identify which wireless network they want to join. A site may have multiple SSIDs, such as staff, guest, and IoT networks.

Authentication and Encryption

Wireless authentication controls who can connect. Wireless encryption protects traffic over the air. WPA2-Personal is simple and useful for small networks, but enterprise networks often use stronger identity-based authentication.

Wireless Is Shared Media

Wired Ethernet switches give each device a dedicated switch port. Wi-Fi clients share airtime on the wireless channel. More clients, interference, distance, and weak signal can reduce performance.

AP Placement

Access points should be placed to provide good coverage without creating unnecessary overlap or interference. In real buildings, walls, metal, glass, distance, and neighboring networks can affect signal quality.

Wireless Security Design

A secure wireless design should consider SSID naming, encryption, password management, guest isolation, management interface security, firmware updates, and monitoring for unauthorized access points.

11. Final Demo Summary

End the demo with this explanation:

When a wireless user opens: http://www.northstar.local the network uses: 1. SSID association to join the wireless network 2. WPA2 authentication to prove the user has the correct key 3. DHCP to receive IP settings 4. DNS to resolve the website name 5. IP routing/NAT behavior through the wireless router 6. TCP port 80 for HTTP 7. Wireless and wired forwarding to reach the server

The most important lesson:

Wireless networking requires both radio-layer access and correct network-layer configuration. A client may connect to Wi-Fi but still fail if DHCP, DNS, gateway, or security settings are wrong.
