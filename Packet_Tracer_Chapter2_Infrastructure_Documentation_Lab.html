Packet Tracer Demo Lab: Infrastructure and Documentation

Chapter 2 companion demo for West’s CompTIA Network+ Guide to Networks, 10th Edition. This version is formatted as an instructor-led demonstration, not a graded student lab.

CourseInternetworking Basics
Duration2-hour lab period
ToolCisco Packet Tracer
FocusPhysical layout, naming, labels, inventory

1. Overview

This demonstration shows how a small business network can be represented, configured, labeled, and documented in Cisco Packet Tracer. The focus is not advanced routing or subnetting. The focus is infrastructure awareness: where devices are located, how links are labeled, how devices are named, and how basic documentation supports troubleshooting.

Demo goal Build one small network in Logical View, organize it in Physical View, configure management addresses, add interface descriptions, and create example documentation tables.

What the audience should see

  • How logical and physical diagrams differ.
  • How MDF and IDF locations organize campus cabling.
  • How interface descriptions reduce guessing.
  • How device names encode role and location.

What this demo avoids

  • No graded deliverables.
  • No assignment evidence checklist.
  • No lab-question section.
  • No submission or rubric section.

2. Demo Scenario

The example organization is Northstar Training Center, a small campus with a Main Building and an Annex Building. The Main Building contains the main telecommunications room, while the Annex contains a smaller wiring closet that uplinks back to the Main Building.

  • City: Northstar City
  • Campus: Northstar Training Campus
  • Main Building: contains the MDF, edge router, main switch, server, AP, and admin PCs
  • Annex Building: contains the IDF, access switch, and user PCs
  • WAN side: represented with a Packet Tracer cloud device

7. Build the Logical Network

Step 1Create the Packet Tracer project

  1. Open Cisco Packet Tracer.
  2. Start in Logical View.
  3. Save the file as Chapter2_Infrastructure_Documentation_Demo.pkt.
  4. Add a note in the upper-left corner: Northstar Training Center — Chapter 2 Demo: Infrastructure and Documentation.

Step 2Add and rename devices

  1. Add one Cloud-PT and rename it ISP-CLOUD-01.
  2. Add one 2911 or 1941 router and rename it RTR-HQ-EDGE-01.
  3. Add two 2960 switches and rename them SW-HQ-MDF-01 and SW-ANNEX-IDF-01.
  4. Add one server and rename it SRV-HQ-WEB-01.
  5. Add four PCs and rename them according to the naming table.
  6. Add one wireless access point and rename it AP-HQ-LOBBY-01.

10. Configure the Router

Open the router CLI. If the initial configuration dialog appears, answer no.

enable
configure terminal
hostname RTR-HQ-EDGE-01

interface gigabitEthernet0/0
 description Uplink to SW-HQ-MDF-01 in Main Building MDF
 ip address 192.168.10.1 255.255.255.0
 no shutdown
 exit

interface gigabitEthernet0/1
 description WAN edge link to ISP-CLOUD-01 / demarc
 ip address 203.0.113.2 255.255.255.252
 no shutdown
 exit

banner motd #Authorized access only. Northstar Training Center network device.#
end
copy running-config startup-config
Teaching point Interface descriptions are documentation inside the device. They help the next technician identify the correct cable, switch, room, or provider connection.

12. Verify Connectivity

Router verification

show ip interface brief
show interfaces description

Expected highlights: G0/0 should be up/up with 192.168.10.1, and G0/1 should be up/up with 203.0.113.2.

Switch verification

show ip interface brief
show interfaces description

Expected highlights: VLAN 1 on the main switch should show 192.168.10.2. VLAN 1 on the annex switch should show 192.168.10.3.

Ping tests

From PC-HQ-ADMIN-01, open Desktop > Command Prompt and run:

ping 192.168.10.1
ping 192.168.10.2
ping 192.168.10.3
ping 192.168.10.10

Then test the web server, if HTTP is enabled:

http://192.168.10.10

13. Simulation Mode Demo

  1. Switch from Real-Time to Simulation.
  2. Clear the event list.
  3. Filter events to ARP and ICMP.
  4. From PC-HQ-ADMIN-01, ping the server: ping 192.168.10.10.
  5. Click Capture / Forward to observe packet movement.
Explain while advancing packets ARP discovers the local MAC address. ICMP carries the ping request and reply. The switch forwards frames based on MAC addresses. Good documentation helps identify which switch ports should be involved in the traffic path.
