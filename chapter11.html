Demo 11.1 — Local AAA and Centralized AAA Concepts

Demo time45 minutes
Devices1 router, 1 switch, 2 PCs, optional AAA server
Primary focusAuthentication, authorization, accounting, SSH

Before class

Prepare an IT management subnet and a user subnet. Optionally add Server-PT with AAA service if supported.

Live demonstration procedure

  1. Configure local usernames with different privilege levels. Explain authentication versus authorization.
  2. Enable SSH and require local login on VTY lines.
  3. From the IT PC, log in with a lower-privilege account, try privileged commands, then log in with an administrative account.
  4. Enable AAA new-model and configure a local fallback method list. Explain why fallback matters if the central server is unavailable.
  5. If using Server-PT AAA, configure matching client/device credentials and user accounts, then point the router to the RADIUS or TACACS+ server.
  6. Test successful login, bad password, unknown username, and server-unavailable behavior.
  7. Explain accounting conceptually: who logged in, when, from where, and what they did. Show available logs if the Packet Tracer service exposes them.
  8. Compare RADIUS and TACACS+ at a conceptual level: combined versus separated authorization, common use cases, and transport differences.

Command reference

aaa new-model
aaa authentication login default local
username viewer privilege 1 secret ViewOnly!
username admin privilege 15 secret AdminOnly!
line vty 0 4
 login authentication default
 transport input ssh

What students should observe

Authentication proves identity; authorization controls permitted actions; accounting records activity. Local fallback can preserve emergency access.

Teaching prompts

Ask students to classify each observed event as authentication, authorization, or accounting.

Packet Tracer limitation

Centralized AAA features vary by Packet Tracer version. Treat the server portion as a concept demonstration rather than exact production syntax.

Demo 11.2 — Port Security Blocks an Unauthorized Device

Demo time35–40 minutes
Devices1 switch, 3 PCs
Primary focusMAC limiting, sticky learning, violation modes

Before class

Connect PC0 to F0/1 as the authorized endpoint. Keep PC1 ready to replace it.

Live demonstration procedure

  1. Configure F0/1 as an access port and enable port security.
  2. Set maximum MAC addresses to 1 and enable sticky learning.
  3. Generate traffic from PC0, then use show port-security interface f0/1 and the running configuration to show the learned sticky MAC.
  4. Disconnect PC0 and connect PC1 to the same port. Generate traffic and observe the violation.
  5. Use show interfaces status and port-security commands to show secure-shutdown or the chosen violation behavior.
  6. Reconnect the authorized PC. Recover the port using shutdown/no shutdown after addressing the cause.
  7. Repeat briefly with restrict or protect mode and compare visibility and operational impact.
  8. Place unused ports into VLAN 999 and shut them down.

Command reference

interface f0/1
 switchport mode access
 switchport port-security
 switchport port-security maximum 1
 switchport port-security mac-address sticky
 switchport port-security violation shutdown
show port-security interface f0/1

What students should observe

Port security binds access behavior to learned MAC addresses, but MAC addresses can be spoofed; it is one layer of defense.

Teaching prompts

Ask: “Which control would provide stronger identity than a MAC address?”
