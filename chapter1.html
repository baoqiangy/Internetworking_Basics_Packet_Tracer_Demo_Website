Demo 1.1 — Follow One Web Request Through the Network

Demo time35–45 minutes
Devices2 PCs, 2 switches, 1 router, 1 server
Primary focusClient/server networking, OSI layers, encapsulation

Before class

Create a blank file. Use a 2911 router, two 2960 switches, two PCs, and one Server-PT. Place PC0 and PC1 on the left LAN and Server0 on the right LAN.

Live demonstration procedure

  1. Cable PC0 and PC1 to Switch0, Switch0 to Router0 G0/0, Router0 G0/1 to Switch1, and Server0 to Switch1. Explain that switches extend a LAN while the router joins different IP networks.
  2. Configure Router0 G0/0 as 192.168.10.1/24 and G0/1 as 192.168.20.1/24. Use no shutdown on both interfaces.
  3. Configure PC0 as 192.168.10.10/24, gateway 192.168.10.1; PC1 as 192.168.10.11/24; Server0 as 192.168.20.10/24, gateway 192.168.20.1.
  4. On Server0, open Services > HTTP and ensure HTTP is On. Edit the home page to display “Internetworking Basics Demo Server.”
  5. From PC0, open Command Prompt and ping 192.168.10.11. Ask why a router is not needed for this traffic.
  6. Ping 192.168.20.10. Explain that PC0 compares the destination with its subnet mask and sends the frame to its default gateway.
  7. Switch to Simulation mode. Clear the event list, select ARP, ICMP, TCP, and HTTP filters, and repeat a ping. Use Capture/Forward one event at a time.
  8. Click each envelope and compare inbound and outbound PDU details. Point out that the Ethernet header changes at the router while the source and destination IP addresses remain end-to-end.
  9. Open PC0 > Web Browser and browse to http://192.168.20.10. Step through ARP, TCP handshake, HTTP request, and HTTP response.
  10. Use Realtime mode again and run tracert 192.168.20.10. Relate each hop to a Layer 3 forwarding decision.

Command reference

enable
configure terminal
interface g0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
interface g0/1
 ip address 192.168.20.1 255.255.255.0
 no shutdown
end
show ip interface brief

What students should observe

Local traffic remains within Switch0. Remote traffic is sent to Router0. Simulation Mode shows ARP before ICMP or TCP when a MAC address is unknown. The webpage loads only after Layer 2, Layer 3, Layer 4, and Layer 7 functions work together.

Teaching prompts

Ask: “Which addresses change at every routed hop?” “Which addresses identify the original endpoints?” “Why does ARP occur before the first ping?”

Demo 1.2 — Peer-to-Peer versus Client–Server

Demo time20 minutes
Devices3 PCs, 1 switch, 1 server
Primary focusNetwork models and services

Before class

Duplicate the left LAN from Demo 1.1 or start with three PCs and a server on one switch.

Live demonstration procedure

  1. Place three PCs and one server in the same subnet. Demonstrate that all devices are peers at the Ethernet/IP connectivity level.
  2. Enable HTTP and FTP on the server. Create an FTP user account.
  3. From a PC, access the server web page and then use the FTP client. Explain centralized service administration.
  4. Use two PCs to exchange simple PDUs directly. Explain that peer-to-peer means a device can provide and consume resources without a dedicated server role.
  5. Disable the server HTTP service and show that all clients lose that centralized service, illustrating a service dependency and possible single point of failure.

What students should observe

Students see that “client” and “server” describe roles during a transaction, while network hardware connectivity can remain identical.

Teaching prompts

Ask students to identify advantages and disadvantages of centralized accounts, backups, permissions, and availability.
