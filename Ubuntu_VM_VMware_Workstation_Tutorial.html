1. Lab overview

Objective: Install a working Ubuntu Desktop virtual machine without replacing or repartitioning Windows. You will use VMware Workstation Pro, a Type-2 desktop hypervisor, to run a separate guest operating system.

Conceptual architecture (not a screenshot): VMware provides virtual hardware, and Ubuntu runs inside its own VM.

Expected result: Ubuntu starts, you can sign in, open Terminal, obtain network access, and create a clean-install snapshot.

2. Prerequisites and recommended settings

These are lab recommendations, not universal hardware minimums. Ensure Windows has sufficient spare resources.

3. Download Ubuntu and VMware

1
Download the Ubuntu Desktop ISO.

On Windows, visit ubuntu.com/download/desktop. Choose Ubuntu 26.04 LTS, Intel or AMD 64-bit, and save the .iso file. The ISO is the installer image; do not extract it or write it to a USB drive for this VM lab.

2
Download VMware Workstation Pro for Windows.

Use Broadcom’s official download instructions. Sign in to or register for a Broadcom Support Portal account if required. Select a current Workstation Pro for Windows release, accept the relevant terms, and download its installer.

VMware Workstation Pro is free for personal, educational, and commercial use under Broadcom's current policy. The Broadcom download process may require account registration and profile verification.
3
Check the downloaded files.

Confirm you have one VMware installer (typically .exe) and an Ubuntu Desktop image (.iso) in your Downloads folder. Optional: verify the Ubuntu ISO SHA256 checksum against the checksum published by Ubuntu.

4. Install VMware Workstation Pro on Windows

1
Launch the VMware installer.

Double-click the Workstation Pro installer. Approve the Windows User Account Control prompt if it appears.

2
Complete the installation wizard.

Accept the license agreement, keep the standard installation directory unless your instructor specifies otherwise, and choose optional shortcuts. Allow the installer to install virtual networking components.

3
Restart if prompted, then launch VMware.

Complete any first-run prompts. Recent versions do not require a paid license key for free use.

If Windows reports that virtualization is unavailable or VMware cannot start VMs, check whether Intel Virtualization Technology / AMD SVM is enabled in the PC’s UEFI/BIOS. Do not disable Windows security features just to resolve a conflict; review VMware compatibility and your institution’s security policies first.

5. Create the Ubuntu virtual machine

1
Start the New Virtual Machine Wizard.

Open VMware Workstation Pro. Select File → New Virtual Machine (or Create a New Virtual Machine).

New Virtual Machine Wizard — conceptual illustration
◉ Typical (recommended)
○ Custom (advanced)
2
Choose Typical configuration.

The Typical wizard is easiest for a first VM. Click Next.

3
Select the operating system image.

Choose Installer disc image file (ISO) and browse to your downloaded Ubuntu .iso. If VMware offers Easy Install, you can use it, but this tutorial follows the manual Ubuntu installer so you can see each setup step. To do that, choose I will install the operating system later and attach the ISO manually in VM settings before powering on.

Manual path recommended for instruction: Choose I will install the operating system later. Select Linux → Ubuntu 64-bit (or the closest supported Ubuntu x86-64 option). After creating the VM, open VM → Settings → CD/DVD, choose Use ISO image file, browse to the downloaded ISO, and check Connect at power on.
4
Choose guest OS.

For manual installation: set guest OS to Linux and version to Ubuntu 64-bit or the closest appropriate entry in your VMware release.

5
Name the VM.

Example: Ubuntu-Desktop-Lab. Select a VM storage location with enough free space, such as C:\VMs\Ubuntu-Desktop-Lab.

6
Specify the virtual disk.

Set 60 GB maximum size. Select Split virtual disk into multiple files for easier transfer, or a single file if preferred. These choices do not normally preallocate the full maximum disk size.

7
Finish wizard, but review settings.

Click Customize Hardware before starting the VM, or use VM → Settings afterward.

7. Install Ubuntu Desktop inside the VM

When the ISO boots, the Ubuntu installer appears. Its exact wording and screen order can change between Ubuntu releases; use the equivalent options shown in your version.

1
Start the installer.

Choose Install Ubuntu (or choose the Ubuntu startup entry, then Install Ubuntu). Wait for the graphical installer to load.

2
Choose language and accessibility options.

Choose English or your required language. Review accessibility preferences, then continue.

3
Choose keyboard layout.

For a typical US classroom environment select English (US) → English (US). Test typing when prompted.

4
Configure network access.

Use the wired/automatic network presented by VMware’s virtual NIC when available. If offline, installation can often continue; apply updates after networking works.

5
Installation mode.

Choose an interactive installation (if offered), and select the default or expanded application selection according to your lab requirements. Either can work; Default provides a smaller desktop setup.

6
Optional software and updates.

Choose to download updates during installation if your connection is stable. Additional third-party drivers/codecs are optional for a basic VM.

7
Disk setup: use the virtual disk.

Choose Erase disk and install Ubuntu (or Erase disk in newer installers) only after verifying you are in the Ubuntu VM and that the target is the 60 GB VMware virtual disk. This erases the VM’s virtual disk, not your Windows host drive, when the VM is configured correctly.

Ubuntu installer — disk selection concept
◉ Erase disk and install Ubuntu
○ Manual partitioning (advanced)
Target: VMware virtual disk (~60 GB) — verify before confirming
Important: The phrase “Erase disk” applies to the disk visible to the guest. Confirm that this is a new virtual disk, not a physical disk passed through to the VM. If disk details are surprising, stop and recheck VMware settings.
8
Create your user account.

Enter your name, a computer name (for example ubuntu-lab), a username (for example student), and a strong password. Select password required at login. Do not use the classroom example as a shared real password.

9
Set time zone.

Choose your local city/time zone. The installer may show a summary; confirm that the intended virtual disk and settings are correct.

10
Install and restart.

Start installation and allow it to finish. Click Restart Now. If prompted to remove installation media, use VMware VM → Removable Devices → CD/DVD → Disconnect (or uncheck connected in settings), then press Enter. The VM should boot from its installed virtual disk, not the ISO.

8. First boot and system updates

1
Sign in to Ubuntu.

Use the username and password created during installation. Complete any welcome or privacy setup prompts.

2
Open Terminal.

Press Ctrl + Alt + T, or open Terminal from the applications list.

3
Update package indexes and installed software.
sudo apt update
sudo apt upgrade -y

Type your password when prompted. Your password characters will not appear while typing.

4
Restart if needed.
sudo reboot
If Ubuntu was installed without internet connectivity, set the VMware network adapter to NAT and verify connectivity before retrying updates.

9. Install VMware guest integration tools

Ubuntu usually uses the open-source open-vm-tools packages. The desktop component supports guest desktop integration; some features depend on VM settings, session type, and VMware version.

1
Install or confirm the tools.
sudo apt update
sudo apt install -y open-vm-tools open-vm-tools-desktop
2
Verify the service.
systemctl status open-vm-tools --no-pager

If the package is installed but the expected service is not listed, check systemctl list-unit-files | grep vmtools; service naming can differ.

3
Restart Ubuntu and test integration.
sudo reboot

Resize the VMware console window; test automatic resolution adjustment. Clipboard copy/paste or drag-and-drop may require enabling Guest Isolation options in VMware settings and may vary under Wayland/X11.

For malware analysis or untrusted cybersecurity labs, disable shared folders, drag-and-drop, and shared clipboard to reduce the chance of data moving between host and guest.

10. Understand Ubuntu VM networking

Logical comparison. Actual visibility depends on host firewall, network configuration, and VMware virtual network settings.

ModeWhat it doesTypical classroom use
NATVM uses VMware's private virtual network and shares host outbound connectivityUbuntu installation, updates, general labs
BridgedVM connects to the physical network as a peer, subject to network rulesWhen an instructor needs the VM reachable on the LAN
Host-onlyVM communicates on a private VMware virtual network with the host and often other VMs; no internet route by defaultIsolated networking or security exercises

Check network details in Ubuntu:

ip -br addr
ip route
ping -c 4 1.1.1.1
ping -c 4 ubuntu.com

If IP ping works but hostname ping fails, investigate DNS. If both fail, inspect the VM network connection and NAT settings. A restricted campus network may block ICMP even while web browsing succeeds.

Cybersecurity note: NAT is convenient but is not a comprehensive security boundary. For intentionally vulnerable targets or attack demonstrations, use a deliberately isolated lab network, avoid connecting them to a production LAN, and verify isolation before running scans.

11. Create a clean-install snapshot

1
Finish all updates and tool installation.

Verify Ubuntu starts and internet access works. For the most predictable snapshot, shut the guest down cleanly.

2
Open Snapshot Manager.

In VMware, use VM → Snapshot → Take a Snapshot (menu labels may differ).

3
Give it a descriptive name.

Example: Ubuntu Clean Install - Updated. Description: “Ubuntu Desktop installed; updates and open-vm-tools complete; NAT network verified.”

4
Know how to restore.

Use Snapshot Manager to revert after an experiment. Reverting discards VM changes made since that snapshot. Save valuable student work elsewhere first.

Snapshots are not backups: they usually depend on the underlying VM files and may increase disk use. Maintain separate backups for important work.

12. Verify installation with commands

Open Terminal and run the following commands. Record the output or take screenshots.

# Ubuntu release and system information
cat /etc/os-release
uname -r

# CPU, memory and available disk space
nproc
free -h
df -h /

# Network configuration
ip -br addr
ip route

# Test DNS/network connectivity
getent hosts ubuntu.com

# Check VMware integration package
dpkg -l open-vm-tools open-vm-tools-desktop
Successful completion criteria: Ubuntu boots to the login screen, you can authenticate, the commands execute, a usable IP address is assigned (for NAT), packages are updated, and a clean snapshot exists.

13. Troubleshooting common issues

“Virtualization is disabled” / VM cannot power on

Check Task Manager → Performance → CPU → Virtualization. If disabled, enable VT-x/SVM in firmware according to the computer manufacturer’s instructions. Reboot and try again. Windows Hyper-V/VBS coexistence behavior varies by VMware release; use current Broadcom troubleshooting guidance rather than turning off security protections indiscriminately.

Black screen or frozen Ubuntu installer

Give the VM sufficient RAM, confirm the ISO is connected, and reboot. If display remains blank, power off the VM and test with Accelerate 3D graphics disabled in Display settings.

“No operating system found” or VM returns to installer

Before installation, check that the ISO is connected at startup. After installation, disconnect the ISO so the VM boots from the newly installed virtual disk. Confirm a hard disk is present in VM settings.

Ubuntu is slow

Use SSD-backed host storage where possible. Close unnecessary host apps, give the VM 4–8 GB RAM without starving Windows, and assign 2 virtual CPUs initially. Do not allocate every CPU core to the guest.

No internet connection

Shut down the VM, verify Network Adapter → NAT, ensure Connected is checked, restart, then run ip route. If still broken, verify the VMware NAT/DHCP services and virtual network settings on the Windows host.

Copy/paste, mouse, or display resize does not work

Install open-vm-tools-desktop, reboot, and examine VMware Guest Isolation settings. Not all integrations work identically under every Wayland/X11 session.

“Not enough disk space”

Check free space on the Windows host: the virtual disk, snapshots, and temporary files all consume physical storage. Remember that 60 GB is the VM’s maximum virtual disk size, not necessarily space already reserved on Windows.

VMware download requires login / “not entitled”

Use the current free Workstation Pro download path in Broadcom’s official article. Complete account/profile checks and agree to any terms required to activate the download.
