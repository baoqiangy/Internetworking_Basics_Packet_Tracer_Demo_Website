Demo 10.1 — Find Risks in an Insecure Router and Switch

Demo time45–55 minutes
Devices1 router, 1 switch, 2 PCs, 1 server
Primary focusRisk identification and hardening

Before class

Prepare a deliberately insecure topology: default names, Telnet, weak passwords, unused ports active, HTTP management, no banner, no management ACL, and a flat LAN.

Live demonstration procedure

  1. Display the running configuration. Ask students to identify assets, threats, vulnerabilities, likelihood, and impact before changing anything.
  2. Create a live risk register with five columns: asset, vulnerability, threat/event, consequence, mitigation. Rank each item High/Medium/Low.
  3. Set hostnames and an enable secret. Configure a local administrator account with a stronger secret.
  4. Configure a domain name and generate RSA keys. Restrict VTY lines to SSH version 2 and local login.
  5. Create a standard ACL permitting only the IT management host and apply it to VTY access with access-class.
  6. Configure service password encryption and a legal warning banner. Explain the limitations of reversible password obfuscation.
  7. Shut down unused switch ports, place them in an unused VLAN, and add descriptions to active ports.
  8. Disable unnecessary services where supported. Save the configuration.
  9. Test Telnet failure, SSH success from the IT PC, and SSH denial from the unauthorized PC.
  10. Revisit the risk register and mark each risk as mitigated, transferred, avoided, or accepted; discuss residual risk.

What students should observe

Hardening reduces attack surface but does not remove all risk. Verification must include both allowed and denied behavior.

Teaching prompts

Ask: “What threat is enabled by this vulnerability?” and “What residual risk remains after the control?”

Packet Tracer limitation

Packet Tracer is not a vulnerability scanner, SIEM, malware sandbox, or realistic penetration-testing platform. Use it to demonstrate configuration risk and control logic.
