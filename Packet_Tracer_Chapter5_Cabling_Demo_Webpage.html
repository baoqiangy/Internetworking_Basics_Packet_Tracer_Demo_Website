1. Demo Purpose

This demo lab introduces the practical cabling ideas students need before they troubleshoot or build larger internetworks. The focus is not advanced routing. The focus is how devices are physically and logically connected, which cable types are used, how ports are selected, and how cabling problems affect connectivity.

Instructor framing: A network can have correct IP addresses and correct device configurations, but communication still fails if the wrong cable, wrong port, disabled interface, or bad physical path is used.

Key Concepts Demonstrated

Copper Ethernet cabling
Use straight-through and crossover cable concepts in Packet Tracer.
Fiber uplink concept
Show why fiber is used between buildings or closets, even if the simulation is simplified.
Console cable
Use a rollover/console connection to manage a router locally.
Interface status
Use show commands to check whether ports are up, down, or administratively down.
Physical workspace
Represent MDF, IDF, cable runs, racks, and telecom spaces.
Cable documentation
Label ports, uplinks, access links, and backbone connections.

2. Demo Scenario

Northstar Training Center has a Main Building and an Annex Building. The Main Building contains the MDF. The Annex Building contains an IDF. The organization wants to connect PCs, a server, a printer, a router, and two switches using correct cabling practices and clear cable documentation.

The instructor will build a small network and demonstrate how cabling choices affect connectivity.

3. Learning Objectives

By the end of this demo, students should be able to explain and observe the following:

  • What straight-through Ethernet cables are commonly used for.
  • What crossover cable historically means and when it may be discussed.
  • Why a console cable is different from a network data cable.
  • How switches, routers, PCs, servers, printers, and access points connect physically.
  • How to identify interface status using Packet Tracer lights and CLI commands.
  • How to document cable runs using labels and a port map.
  • How a disconnected cable or shutdown interface causes network failure.
  • Why backbone/uplink cabling between closets is documented separately from user access cabling.

14. Part F — Verify Cabling and Interfaces

Visual Link Status

In Packet Tracer, observe the link lights. Green usually indicates the link is up. Amber may appear while spanning tree or interface negotiation is occurring. Red indicates a disconnected or down link.

Router Checks

show ip interface brief
show interfaces description
show interfaces gigabitEthernet0/0

Expected idea:

GigabitEthernet0/0     192.168.50.1     YES manual up     up

Switch Checks

On each switch, use:

show interfaces status
show interfaces description
show mac address-table

Instructor explanation:

  • show interfaces status helps identify connected ports.
  • show interfaces description confirms that documentation exists inside the configuration.
  • show mac address-table confirms that the switch is learning devices on active ports.

Ping Tests

From PC-HQ-ADMIN-01, open Command Prompt and run:

ping 192.168.50.1
ping 192.168.50.2
ping 192.168.50.3
ping 192.168.50.10
ping 192.168.50.31
ping 192.168.50.40
When these pings work, the basic LAN cabling, switch forwarding, router LAN interface, and end-device IP settings are all functioning.

17. Optional Part I — Serial WAN Cable Demonstration

This section is optional. It is useful when the instructor wants to show that different network environments may use different cable and interface types.

Add Serial Interfaces if Needed

Some Packet Tracer routers may need a serial module added in the Physical tab. Power off the router, insert a serial module such as WIC/HWIC serial if available, then power the router back on.

Connect the Routers

RTR-HQ-EDGE-01 Serial0/0/0  -->  RTR-WAN-DEMO-01 Serial0/0/0

Use the serial DCE/DTE cable. One side acts as the DCE side and may require a clock rate.

Example Configuration

On RTR-HQ-EDGE-01:

configure terminal
interface serial0/0/0
description Serial WAN demo link to RTR-WAN-DEMO-01
ip address 10.10.10.1 255.255.255.252
clock rate 64000
no shutdown
end

On RTR-WAN-DEMO-01:

enable
configure terminal
hostname RTR-WAN-DEMO-01
interface serial0/0/0
description Serial WAN demo link to RTR-HQ-EDGE-01
ip address 10.10.10.2 255.255.255.252
no shutdown
end

Verify:

show ip interface brief
ping 10.10.10.2
If clock rate is rejected, the selected router interface is not the DCE side. Apply the clock rate on the other router serial interface, or use this as a teaching moment about DCE/DTE roles.

19. Part K — Cabling Troubleshooting Demonstrations

Demo 1: Disconnected Access Cable

Delete or disconnect the cable between:

PC-ANNEX-USER-01 Fa0  -->  SW-ANNEX-IDF-01 Fa0/1

From PC-ANNEX-USER-01, try:

ping 192.168.50.1
ping 192.168.50.10

Both tests should fail because the PC is physically disconnected.

Instructor explanation: If one user is down, check that user's cable, wall jack, patch panel path, and switch port first.

Demo 2: Disconnected Backbone/Uplink Cable

Reconnect the access cable. Then disconnect the uplink between:

SW-HQ-MDF-01 G0/2  -->  SW-ANNEX-IDF-01 G0/1

Now test from PC-ANNEX-USER-01:

ping 192.168.50.1
ping 192.168.50.10

The Annex devices lose access to the Main Building network.

Instructor explanation: A backbone/uplink failure can affect many devices behind the downstream switch.

Demo 3: Administratively Shutdown Port

On SW-ANNEX-IDF-01, shut down the port connected to the annex PC:

enable
configure terminal
interface fastEthernet0/1
shutdown
end

Verify:

show interfaces status
show ip interface brief

Fix:

configure terminal
interface fastEthernet0/1
no shutdown
end

Instructor explanation: A cable may be physically connected, but the port may still be disabled in software.

Demo 4: Wrong Port Documentation

Move PC-HQ-ADMIN-01 from Fa0/2 to Fa0/10 without updating the label.

Run:

show mac address-table
show interfaces status

Instructor explanation: The network may still work, but documentation is now wrong. Incorrect documentation can cause technicians to troubleshoot the wrong port or unplug the wrong device.

Switch to Simulation Mode. Filter for ARP and ICMP.

Explain:

  • The user sees a simple ping.
  • Packet Tracer shows frames moving across cables.
  • The switch forwards frames through specific ports.
  • If a cable or port fails, the packet cannot complete the path.

21. Instructor Talking Points

Straight-Through vs. Crossover

Traditionally, straight-through cables connect different device types, such as PC-to-switch or router-to-switch. Crossover cables historically connected similar device types, such as switch-to-switch or PC-to-PC. Modern network interfaces often support auto-MDIX, so the device may automatically adjust. Packet Tracer may also simplify this behavior.

Copper vs. Fiber

Copper cabling is common for short access runs inside an office. Fiber is often preferred for longer distances, building-to-building uplinks, high-speed backbone links, and areas where electromagnetic interference or electrical grounding issues are a concern.

Console vs. Ethernet

A console cable provides management access to the command-line interface. It does not provide normal IP connectivity between devices. This is why a technician can use a console connection even when the network interface has no IP address.

Physical Layer Troubleshooting Comes First

Before changing IP settings or routing tables, check whether the cable is connected, the link light is active, the correct port is used, and the interface is enabled.

23. Final Demo Summary

End the demo with this summary:

Main lesson: Cabling is the foundation of network communication. If the physical path is wrong, missing, disabled, mislabeled, or poorly documented, higher-layer services cannot work reliably.

Key Takeaways

  • Use appropriate cable types for the connection being demonstrated.
  • Label links clearly in the logical topology.
  • Use Physical View to show MDF, IDF, and device placement.
  • Use CLI commands to verify port status and interface descriptions.
  • Use ping and Simulation Mode to connect cabling concepts to actual packet movement.
  • Document backbone/uplink cables carefully because they affect multiple downstream devices.

Simple Troubleshooting Order

1. Check the cable.
2. Check the link light.
3. Check the correct port.
4. Check whether the interface is shut down.
5. Check IP configuration.
6. Check higher-layer services.
