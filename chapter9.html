Demo 9.1 — Connect Headquarters and Branches Across a Provider

Demo time50 minutes
Devices4 routers, 3 LAN switches, 3 PCs
Primary focusWAN links, edge/provider roles, routing

Before class

Build HQ, Branch1, Branch2, and ISP routers. Use /30 WAN links and /24 site LANs.

Live demonstration procedure

  1. Label customer edge and provider devices. Explain demarcation of responsibility.
  2. Configure site LAN interfaces and WAN interfaces. On serial DCE ends, configure clock rate.
  3. At each branch, configure a default route toward the ISP. On the ISP, configure routes back to customer LANs.
  4. Ping the local gateway, then ISP next hop, then a remote branch PC. Show progressive testing.
  5. Use tracert to identify the path across the provider.
  6. Delete one ISP return route and demonstrate one-way reachability symptoms or failed replies.
  7. Restore the route and then shut a WAN interface to simulate carrier failure. Use interface status and routing tables to isolate the problem.
  8. Compare static routing with what a dynamic routing protocol would automate.

Command reference

ip route 0.0.0.0 0.0.0.0 198.51.100.1
show ip route
show interfaces serial 0/0/0
traceroute 192.168.30.10

What students should observe

Site routers depend on a default route; the provider needs return-path knowledge. Successful delivery requires routing in both directions.

Teaching prompts

Ask: “Why can the outbound packet reach the branch but the reply still fail?”

Demo 9.2 — GRE Tunnel as a VPN Concept Demonstration

Demo time35–45 minutes
Devices2 customer routers plus ISP
Primary focusTunneling, overlay versus underlay

Before class

Use two private LANs behind customer routers connected through an ISP. Verify normal routed reachability between public WAN addresses.

Live demonstration procedure

  1. Configure Tunnel0 on each customer router with a private tunnel IP address.
  2. Set tunnel source to the local WAN interface and tunnel destination to the remote public WAN address.
  3. Add routes to the remote private LAN through the tunnel interface.
  4. Use show interfaces tunnel 0 and show ip route.
  5. Ping between private LAN hosts and use traceroute. Explain that the overlay path is logical while the ISP underlay carries encapsulated packets.
  6. Shut the underlying WAN interface and show that the tunnel also fails.
  7. Explain that GRE provides encapsulation, not confidentiality; production designs commonly combine tunneling with IPsec or use another encrypted VPN technology.

Command reference

interface tunnel 0
 ip address 10.255.0.1 255.255.255.252
 tunnel source g0/1
 tunnel destination 198.51.100.2
ip route 192.168.20.0 255.255.255.0 tunnel 0
show interfaces tunnel 0

What students should observe

The tunnel creates a logical point-to-point overlay across the provider network, but it depends on underlay reachability.

Teaching prompts

Ask students to distinguish encapsulation, authentication, integrity, and encryption.

Packet Tracer limitation

Packet Tracer support for IPsec, remote-access VPNs, SD-WAN, MPLS, and provider services varies. GRE is used here to visualize the core tunneling concept.
