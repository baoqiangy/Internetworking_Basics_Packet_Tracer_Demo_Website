Cisco Packet Tracer Demo Lab:
Port Mirroring (SPAN)

Step-by-step classroom demonstration with topology diagrams, switch commands, expected behavior, fallback workflow, and troubleshooting.

Contents

    1. Lab Overview

    Port mirroring, also called Switched Port Analyzer (SPAN) on Cisco switches, copies network traffic from a source switch port to a designated destination port for monitoring.

    It is commonly used for network troubleshooting, packet analysis, intrusion detection systems (IDS), and network security monitoring.

    In this demonstration, we will configure a switch to mirror traffic from PC0 to a monitoring port connected to PC2.

    Important Packet Tracer limitation: SPAN commands are implemented only on some simulated switch models and versions. Older Packet Tracer demonstrations have used the 2950 switch successfully, but current behavior varies. The first step is to verify command support. Also, Packet Tracer's Simulation Mode is not equivalent to capturing actual mirrored Ethernet frames with Wireshark.

    2. Network Topology

    Devices

    • 1 Cisco switch supporting SPAN (try 2950 first).
    • 3 PCs: PC0, PC1, PC2.
    • 3 copper straight-through cables.

    Connections

    DeviceSwitch portPurpose
    PC0Fa0/1Source traffic
    PC1Fa0/2Communication peer
    PC2Fa0/3Monitoring destination

    IP addressing

    DeviceIP addressSubnet mask
    PC0192.168.10.10255.255.255.0
    PC1192.168.10.20255.255.255.0
    PC2192.168.10.30255.255.255.0

    No router or default gateway is required.

    3. Step 1 — Build the Network

    1. Open Cisco Packet Tracer.
    2. Add one 2950 switch from Network Devices → Switches, if available.
    3. Add three PCs from End Devices.
    4. Select Connections → Copper Straight-Through.
    5. Connect the PCs to Fa0/1, Fa0/2, and Fa0/3 as shown.

    Wait for the switch interfaces to become active.

    4. Step 2 — Configure the PC IP Addresses

    On each PC:

    1. Click the PC.
    2. Choose Desktop → IP Configuration.
    3. Set the IPv4 address and subnet mask using the table above.
    4. Leave Default Gateway blank.

    Verify connectivity before configuring SPAN. On PC0, open Desktop → Command Prompt:

    ping 192.168.10.20

    Expected output:

    Reply from 192.168.10.20: bytes=32 time<1ms TTL=128
Reply from 192.168.10.20: bytes=32 time<1ms TTL=128

    Initial ARP resolution can cause the first ping to time out.

    Explain: PC0 and PC1 communicate through the switch. Normally, the switch does not send their known unicast traffic to PC2.

    5. Step 3 — Verify SPAN Command Support

    On Switch0, open the CLI tab:

    enable
configure terminal
monitor ?

    If supported, the switch should offer the session command or related monitoring syntax.

    Then try:

    end
show monitor

    If you receive:

    % Invalid input detected at '^' marker.

    the selected switch model may not support SPAN in your Packet Tracer version.

    Instructor note: Try another available 2950 model. Do not assume that the Packet Tracer 2960 supports all the SPAN features found on a physical Catalyst 2960. Real IOS syntax is documented by Cisco, but simulated feature availability differs.

    6. Step 4 — Configure Port Mirroring

    Assuming the selected switch supports SPAN, enter:

    enable
configure terminal

monitor session 1 source interface fastEthernet0/1 both
monitor session 1 destination interface fastEthernet0/3

end

    If your model accepts abbreviated interface names, use fa0/1 and fa0/3.

    Command explanation

    CommandMeaning
    monitor session 1Creates or modifies SPAN session 1
    source interface fa0/1Selects the port to monitor
    bothMirrors received and transmitted traffic
    destination interface fa0/3Sends copies to the monitoring port

    Direction options:

    • rx: Traffic received by the source port.
    • tx: Traffic transmitted from the source port.
    • both: Both directions.
    Explain: The SPAN destination is no longer used as an ordinary data-switching port while the session is active. Its purpose is to receive copied frames.

    7. Step 5 — Verify the SPAN Configuration

    On the switch:

    show monitor

    Expected information (format varies):

    Session 1
---------
Source Ports:
    Both: Fa0/1

Destination Ports:
    Fa0/3

    Also check the running configuration:

    show running-config

    Look for monitoring commands. If unsupported or missing, stop the real SPAN portion and use the fallback demonstration in Section 10.

    8. Step 6 — Generate Traffic

    On PC0:

    ping 192.168.10.20

    Run the command multiple times. This generates ICMP Echo Request and Echo Reply packets between PC0 and PC1.

    Important: Successful ping responses show connectivity, not that mirroring actually works.

    9. Step 7 — Observe Packets in Simulation Mode

    1. Switch Packet Tracer from Realtime to Simulation.
    2. Open Edit Filters.
    3. Select ICMP and ARP.
    4. On PC0, generate another ping.
    5. Click Capture/Forward to step through events.
    6. Click the packet envelope to examine protocol details, including source and destination addresses.

    Packet Tracer lets you visualize forwarding and protocol headers. However, do not treat a packet animation at PC2 as definitive SPAN verification. Some versions may accept SPAN configuration without accurately simulating packet mirroring.

    Genuine validation requires seeing copies of PC0's traffic on the monitoring interface. For reliable packet capture validation, use a physical SPAN-capable switch and Wireshark, or a suitable network emulator. Packet Tracer's simulation packets are not directly capturable in an external Wireshark session.

    10. Fallback Demo — When SPAN Is Unsupported

    If monitor session is not recognized, use Packet Tracer to demonstrate conventional switching and explain the SPAN difference.

    Step A. Generate traffic without SPAN

    On PC0:

    ping 192.168.10.20

    In Simulation Mode, step through ICMP forwarding after ARP resolution. Explain that a switch normally directs a known unicast frame only toward the port associated with the destination MAC address.

    Step B. Examine the MAC address table

    On Switch0:

    show mac address-table

    Find the MAC addresses learned on Fa0/1 and Fa0/2.

    Step C. Explain how SPAN would change monitoring

    Without SPAN, PC2 generally does not receive known unicast packets exchanged by PC0 and PC1. With SPAN, a dedicated monitoring port receives copies matching the configured source and direction.

    This fallback teaches the concept, but it is not a functioning port-mirroring lab. Present it as visualization of ordinary switching followed by an explanation of SPAN.

    11. Step 8 — Remove Port Mirroring

    On a switch supporting the configuration:

    enable
configure terminal
no monitor session 1
end

    Verify:

    show monitor

    The session should no longer appear.

    Explain: Removing SPAN returns the port to normal operation, subject to its remaining interface configuration.

    12. Important Concepts

    ConceptExplanation
    Source portInterface whose traffic is monitored
    Destination portInterface receiving mirrored copies
    SPANLocal port or VLAN mirroring on a switch
    RSPANRemote SPAN using a designated VLAN
    ERSPANEncapsulates mirrored traffic for transport over an IP network
    RXFrames entering the monitored interface
    TXFrames leaving the monitored interface
    IDSIntrusion Detection System that can analyze mirrored traffic

    Main takeaway

    Port mirroring allows a network administrator to observe traffic passing through a switch without placing the monitoring device directly in the original communication path.

    It is foundational for passive network monitoring, IDS deployment, network troubleshooting, and forensic traffic analysis.

    Official reference: Cisco: Configuring SPAN and RSPAN.
