Demo 3.1 — Subnet a /24 with VLSM

Demo time45–55 minutes
Devices1 router, 4 switches, 8 PCs
Primary focusIPv4 addressing, masks, gateways, VLSM

Before class

Use network 192.168.50.0/24. Prepare four LANs: 50, 25, 12, and 6 hosts.

Live demonstration procedure

  1. Write the host requirements on screen. Start with the largest network and determine the smallest prefix that supports it: /26, /27, /28, and /29.
  2. Build four LANs connected to four router interfaces or use two routers if the selected model has too few Ethernet ports.
  3. Assign subnets sequentially: 192.168.50.0/26, .64/27, .96/28, and .112/29. Identify network, usable range, and broadcast address for each.
  4. Configure each router interface with the first usable address. Configure two sample hosts per LAN using later usable addresses and the correct gateway.
  5. Use show ip interface brief to verify interface state, then ping within a LAN and across LANs.
  6. On one host, intentionally enter 255.255.255.0 instead of the assigned VLSM mask. Show that some destinations may be incorrectly treated as local and ARP attempts fail.
  7. Correct the mask, then deliberately enter the wrong default gateway. Compare the symptom: same-subnet ping works, remote-subnet ping fails.
  8. Use Simulation Mode to show the different behavior caused by a mask error versus a gateway error.

Command reference

show ip interface brief
show ip route
show arp

! Example interface
interface g0/0
 ip address 192.168.50.1 255.255.255.192
 no shutdown

What students should observe

Correctly addressed hosts reach all four networks because all routes are directly connected. A wrong mask changes the host’s local/remote decision; a wrong gateway prevents off-subnet delivery.

Teaching prompts

Pause before each correction and ask students to predict whether local and remote pings will work.

Demo 3.2 — DHCP, DNS, and Dual-Stack IPv6

Demo time45 minutes
Devices1 router, 2 switches, 3 PCs, 1 server
Primary focusDHCP DORA, DNS, IPv6 addressing and NDP

Before class

Create two LANs: Users 10.10.10.0/24 and Servers 10.10.20.0/24. Use the router as DHCP server and Server0 as DNS/HTTP server.

Live demonstration procedure

  1. Configure router interfaces for both IPv4 networks and add IPv6 addresses 2001:db8:10::1/64 and 2001:db8:20::1/64. Enable ipv6 unicast-routing.
  2. Configure Server0 statically as 10.10.20.10 and 2001:db8:20::10/64. Enable HTTP and DNS; create an A record www.demo.local → 10.10.20.10.
  3. On the router, exclude infrastructure addresses and create a DHCP pool for Users including default gateway and DNS server.
  4. Set PC0 and PC1 to DHCP. Show the assigned address, mask, gateway, and DNS values.
  5. In Simulation Mode, filter DHCP and renew a client address. Step through Discover, Offer, Request, and Acknowledgment.
  6. Browse to www.demo.local. Filter DNS and HTTP and show name resolution before the web connection.
  7. Configure PCs for IPv6 Auto Config. Show global and link-local addresses. Ping the server’s IPv6 address.
  8. Filter ICMPv6 and demonstrate Neighbor Solicitation/Advertisement. Contrast NDP with IPv4 ARP.

Command reference

ipv6 unicast-routing
ip dhcp excluded-address 10.10.10.1 10.10.10.20
ip dhcp pool USERS
 network 10.10.10.0 255.255.255.0
 default-router 10.10.10.1
 dns-server 10.10.20.10
 domain-name demo.local
interface g0/0
 ipv6 address 2001:DB8:10::1/64
interface g0/1
 ipv6 address 2001:DB8:20::1/64

What students should observe

DHCP automates four IPv4 settings, DNS maps names to addresses, and IPv6 clients have both link-local and global addresses. IPv6 uses ICMPv6 Neighbor Discovery rather than ARP.

Teaching prompts

Ask students to predict what breaks if the DHCP pool gives the correct IP address but the wrong DNS server.
