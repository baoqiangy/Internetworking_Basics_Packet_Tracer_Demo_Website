Nmap Demonstration on Ubuntu

Instructor-led demo30–40 minutesUbuntu 22.04 / 24.04+

A step-by-step live demonstration of host discovery, port scanning, service enumeration, and exporting results using Nmap.

Scope: Scan only your own local machine or an isolated network for which you have explicit permission. The default target below is 127.0.0.1.

1. Install Nmap

Open Ubuntu Terminal and run:

sudo apt update
sudo apt install nmap -y

Verify:

nmap --version
Explain: Nmap is a network discovery and security scanning tool used to identify hosts, ports, and network services.

2. Identify the Ubuntu IP Address

ip addr

Alternatively:

hostname -I

Example: 192.168.56.10. An IP address identifies an interface on a network; Nmap accepts IP addresses or hostnames as targets.

3. Set Up a Test Web Server

Create a web page and launch a local HTTP server:

mkdir -p ~/nmap-demo
cd ~/nmap-demo
echo "Welcome to Nmap Demo" > index.html
python3 -m http.server 8080 --bind 127.0.0.1

Leave the terminal open. In a second terminal:

curl http://127.0.0.1:8080

Expected output:

Welcome to Nmap Demo
Explain: The Python server listens on TCP port 8080. Nmap will discover the listening port.

4. Perform a Basic Port Scan

nmap 127.0.0.1
nmap -p 8080 127.0.0.1

Illustrative output:

PORT     STATE SERVICE
8080/tcp open  http-proxy

Explain: open means a service accepts connections. The service label is a port-based guess unless service detection is enabled.

5. Scan Multiple Ports

Selected ports:

nmap -p 22,80,443,8080 127.0.0.1

Port range:

nmap -p 8000-8100 127.0.0.1

All TCP ports:

nmap -p- 127.0.0.1
Explain: A default Nmap port scan usually checks the 1,000 most common TCP ports. -p- checks ports 1–65535.

6. Compare TCP Connect and SYN Scans

TCP Connect:

nmap -sT -p 8080 127.0.0.1

TCP SYN:

sudo nmap -sS -p 8080 127.0.0.1
FeatureTCP Connect (-sT)TCP SYN (-sS)
Full TCP handshakeYesNormally no
Elevated privilegesGenerally not neededGenerally needed
Identify open portsYesYes
BehaviorFull connectionSYN probe, then typically reset

Explain: SYN scans generally avoid completing a TCP connection, but they can still be logged and detected.

7. Detect Service Versions

nmap -sV -p 8080 127.0.0.1

Illustrative result (exact detection will vary):

PORT     STATE SERVICE VERSION
8080/tcp open  http    Python http.server ...

Explain: -sV sends additional probes to identify the actual application behind an open port.

8. Discover Hosts on a Private Lab Network

For an isolated subnet you control:

sudo nmap -sn 192.168.56.0/24

Explain: -sn performs host discovery without port scanning. Depending on the network, Nmap may use ARP, ICMP, or other probes. Replace the example network with your authorized subnet.

9. Demonstrate UDP Scanning

sudo nmap -sU -p 53,123,161 127.0.0.1

Explain: UDP is connectionless; without a clear response Nmap may classify a port as open|filtered.

10. Demonstrate Operating System Detection

With a second VM connected to the isolated lab network:

sudo nmap -O 192.168.56.20

Explain: Nmap fingerprints network responses to estimate the OS. It may return an uncertain result or fail when the response evidence is insufficient.

11. Save Scan Results

Save human-readable text:

nmap -sV -p 8080 127.0.0.1 -oN result.txt
cat result.txt

Save XML:

nmap -sV -p 8080 127.0.0.1 -oX result.xml

Save in multiple formats:

nmap -sV -p 8080 127.0.0.1 -oA demo

This produces demo.nmap, demo.xml, and demo.gnmap.

Wrap-Up: Verify a Port Closes

In the server terminal press Ctrl + C, then:

nmap -p 8080 127.0.0.1

The port should change from open to closed, assuming no other application is listening.
