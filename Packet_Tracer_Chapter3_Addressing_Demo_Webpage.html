1. Lab Purpose

The purpose of this demo lab is to help students understand how devices are identified and located on a network.

In Chapter 2, the focus was infrastructure and documentation. In Chapter 3, the focus moves to addressing.

Students should see that communication on a network depends on several different types of addresses:

  • MAC addresses identify network interfaces at the Data Link layer.
  • IPv4 addresses identify hosts and networks at the Network layer.
  • Port numbers identify services and applications at the Transport layer.
  • Domain names provide human-readable names for network resources.
  • DNS translates names into IP addresses.
  • DHCP automatically assigns IP settings to clients.

2. Lab Scenario

You are demonstrating the network for Northstar Training Center.

The organization has one small office network with:

  • One router
  • One switch
  • One server
  • Three wired PCs
  • One local DNS and DHCP server

The demo shows how addressing works inside the LAN:

  1. How to view MAC addresses.
  2. How a switch learns MAC addresses.
  3. How to configure static IPv4 addresses.
  4. How DHCP assigns addresses automatically.
  5. How DNS resolves a domain name to an IP address.
  6. How port numbers identify services.
  7. How to troubleshoot addressing problems using common commands.

3. Learning Objectives

By the end of this instructor-led demo, students should be able to:

  1. Explain the difference between a MAC address and an IP address.
  2. Locate a MAC address on a PC and switch.
  3. Explain how ARP helps devices communicate on a LAN.
  4. Configure static IPv4 settings on a Packet Tracer PC.
  5. Configure DHCP service on a Packet Tracer server.
  6. Configure DNS service on a Packet Tracer server.
  7. Use a domain name to reach a local web server.
  8. Explain how port numbers relate to network services.
  9. Use ping, ipconfig, nslookup, and Packet Tracer Simulation Mode.
  10. Diagnose simple addressing problems.

14. Configure the Router

Click RTR-HQ-EDGE-01 and open the CLI tab. If prompted to enter the initial configuration dialog, type no.

enable
configure terminal
hostname RTR-HQ-EDGE-01
interface gigabitEthernet0/0
description LAN default gateway for 192.168.30.0/24
ip address 192.168.30.1 255.255.255.0
no shutdown
exit
banner motd #Authorized access only. Northstar Training Center gateway router.#
end
copy running-config startup-config

Verify the router interface:

show ip interface brief

Expected key result:

GigabitEthernet0/0     192.168.30.1    YES manual up     up
Instructor explanation: The router interface 192.168.30.1 is the default gateway for the LAN. Devices use it when they need to reach another network.

17. Test Basic Connectivity

On PC-HQ-STATIC-01, open Desktop > Command Prompt.

ipconfig
ping 192.168.30.1
ping 192.168.30.10

Expected result: replies from the router and server.

This confirms that the cable is connected, the switch is forwarding frames, the PC settings are valid, the router interface is up, and the server IP settings are valid.

18. View MAC Addresses

View the PC MAC address

On PC-HQ-STATIC-01, open Desktop > Command Prompt and run:

ipconfig /all

Look for the physical address, for example:

Physical Address................: 00D0.BA12.3456

View the server MAC address

Click SRV-HQ-SERVICES-01, then go to Config > FastEthernet0 and look for the MAC address.

A MAC address is used for local Ethernet delivery inside the LAN.

19. View the Switch MAC Address Table

Click SW-HQ-ACCESS-01, open CLI, and run:

enable
show mac address-table

At first, the table may be empty or may show only a few entries.

Return to PC-HQ-STATIC-01 and ping the server:

ping 192.168.30.10

Return to the switch and run:

show mac address-table

The switch should now know MAC addresses on ports such as Fa0/2 and Fa0/3.

Instructor explanation: A switch learns MAC addresses by reading the source MAC address of frames entering its ports. This is why switches are Layer 2 devices.

20. Observe ARP and ICMP in Simulation Mode

  1. Click Simulation in the lower-right corner.
  2. Clear the existing event list.
  3. Set event filters to show ARP and ICMP.

On PC-HQ-STATIC-01, run:

arp -d
ping 192.168.30.10

If Packet Tracer does not support arp -d in your version, use a newly opened file or power-cycle the PC.

Click Capture / Forward and observe:

  1. ARP request from PC.
  2. ARP reply from server.
  3. ICMP echo request.
  4. ICMP echo reply.

Before the PC can send the ICMP packet to the server, it needs the server’s MAC address. Ethernet delivery requires a destination MAC address.

31. Troubleshooting Demo 1: Wrong IP Address

On PC-HQ-STATIC-01, go to Desktop > IP Configuration and change the IP address to:

IP Address:       192.168.40.21
Subnet Mask:      255.255.255.0
Default Gateway:  192.168.30.1

Then test:

ping 192.168.30.10
ipconfig

The PC is now in 192.168.40.0/24, but the server is in 192.168.30.0/24. The fix is to restore the PC to:

IP Address:       192.168.30.21
Subnet Mask:      255.255.255.0
Default Gateway:  192.168.30.1
DNS Server:       192.168.30.10

33. Troubleshooting Demo 3: DHCP Failure

On SRV-HQ-SERVICES-01, go to Services > DHCP and turn DHCP Off.

On PC-HQ-DHCP-01, go to Desktop > IP Configuration, switch to Static, then switch back to DHCP. If supported, try:

ipconfig /renew

If DHCP is unavailable, a client may fail to receive a valid address, keep an old address temporarily, or show other addressing problems. Turn DHCP back On and request DHCP again.

34. Troubleshooting Demo 4: Duplicate IP Address

On PC-HQ-DHCP-02, temporarily change from DHCP to Static and enter the same address used by PC-HQ-STATIC-01:

IP Address:       192.168.30.21
Subnet Mask:      255.255.255.0
Default Gateway:  192.168.30.1
DNS Server:       192.168.30.10

Test connectivity from both PCs. Packet Tracer may show inconsistent behavior, conflict warnings, or confusing results.

Two devices should not use the same IP address on the same network. Duplicate IP addresses can cause intermittent connectivity, ARP confusion, wrong-device delivery, and difficult troubleshooting.

Fix the problem by returning PC-HQ-DHCP-02 to DHCP and confirming it receives a unique address.

37. Same-Subnet Communication

When PC-HQ-STATIC-01 sends traffic to SRV-HQ-SERVICES-01:

PC:     192.168.30.21/24
Server: 192.168.30.10/24

Both devices are in:

192.168.30.0/24

So the PC sends traffic directly to the server’s MAC address. The switch forwards the Ethernet frame inside the LAN. The router is not needed for same-subnet communication.

38. DHCP vs. Static IP

Static IP Addressing

Advantages: predictable, good for servers and infrastructure, easier to document.

Disadvantages: more manual work, more chance of typing errors, possible duplicate addresses.

DHCP Addressing

Advantages: automatic, scalable, reduces manual configuration, good for clients.

Disadvantages: depends on DHCP availability, requires scope planning, addresses may change.

39. DNS Troubleshooting Logic

Can the client ping the server by IP address?

If no:
  Check IP address, subnet mask, cable, switch, and server status.

If yes:
  Can the client access the server by domain name?

If no:
  Check DNS server setting, DNS service status, and DNS records.

42. Final Demo Summary

At the end of the demo, summarize the addressing process like this:

When a user accesses:

http://www.northstar.local

the network uses several addressing systems:

  1. The domain name identifies the resource in human-friendly form.
  2. DNS translates the name to an IP address.
  3. The IP address identifies the destination host.
  4. TCP port 80 identifies the HTTP service.
  5. ARP finds the destination MAC address for local delivery.
  6. The switch uses MAC addresses to forward frames.
  7. The server responds to the client.
Most important lesson: Network communication works only when each layer has the correct addressing information.
