Demo 4.1 — Watch ARP, DNS, TCP, UDP, and HTTP

Demo time40 minutes
Devices1 PC, 1 switch, 1 server
Primary focusProtocol stack and port numbers

Before class

Place a PC and Server0 on one LAN. Enable DNS, HTTP, FTP, and email on Server0.

Live demonstration procedure

  1. Assign static IP addresses and verify ping.
  2. Create DNS records for www.demo.local, ftp.demo.local, and mail.demo.local.
  3. Enter Simulation Mode and clear all filters. Select only ARP and ICMP. Ping the server and inspect the first ARP exchange.
  4. Clear events, select DNS, TCP, and HTTP. Browse to www.demo.local. Step through the DNS query/response, TCP three-way handshake, HTTP request, and response.
  5. Open PDU details and point out UDP port 53 for the DNS exchange and TCP destination port 80 for HTTP.
  6. Use FTP from the PC and observe control traffic. Explain that protocols may use multiple logical conversations.
  7. Configure an email account on Server0 and PC0; send a message to a second account. Observe SMTP and POP3 events.
  8. Use the OSI Model tab in PDU Information to narrate encapsulation from application data down to bits and decapsulation at the receiver.

What students should observe

A single user action often triggers multiple protocols. Port numbers identify receiving applications, while IP and MAC addresses identify network and local-link destinations.

Teaching prompts

Ask: “Which protocols are connection-oriented?” “Which address is used only on the local segment?” “Why might DNS use UDP?”

Demo 4.2 — Static Routes versus OSPF

Demo time45–55 minutes
Devices3 routers, 3 switches, 3 PCs
Primary focusRouting tables, next hops, convergence

Before class

Build a triangle of three routers, each with a LAN. Use /30 point-to-point networks and /24 LANs.

Live demonstration procedure

  1. Configure all interfaces and verify directly connected links.
  2. Display show ip route. Point out C and L routes and explain why remote LANs are absent.
  3. Add static routes to every remote LAN. Ping end to end and use tracert.
  4. Count the number of static route statements and discuss scaling.
  5. Remove the static routes. Configure OSPF process 1 in area 0 on all routers using network statements or interface OSPF commands.
  6. Use show ip ospf neighbor and show ip route. Identify routes marked O.
  7. Start a continuous ping or repeatedly ping between edge LANs. Shut one inter-router link and show OSPF selecting the alternate path.
  8. Bring the link back and explain convergence, metric, and why dynamic routing is useful in changing topologies.

Command reference

router ospf 1
 router-id 1.1.1.1
 network 10.0.0.0 0.0.0.255 area 0
 network 192.168.1.0 0.0.0.255 area 0
show ip ospf neighbor
show ip route ospf

What students should observe

Static routing works but requires manual entries. OSPF forms neighbor relationships, exchanges topology information, and updates routes after a failure.

Teaching prompts

Ask students to predict which path OSPF will use based on interface cost.
